Přehled funkcionalit — fáze implementace

MVP — Fáze 1 jádro

  • Hierarchický outliner (uzly, vnoření, přesun)
  • Supertagy s vlastními poli (text, datum, výběr, číslo)
  • Panel polí pro vybraný uzel
  • Denní poznámky (auto #DailyNote)
  • Local-first úložiště (IndexedDB / SQLite)
  • Web app (PWA) + Windows desktop (Tauri)
  • Tmavý / světlý režim

Fáze 2 — Pokročilé supertagy

  • Reference mezi uzly (#Person → #Task)
  • Dědičnost supertagů (#Entity → #Task)
  • Šablony obsahu při vytvoření uzlu
  • Live dotazy s vizuálním builderem
  • Uložené dotazy v sidebaru
  • Fulltextové vyhledávání

Fáze 3 — Sync & kolaborace

  • Synchronizace mezi zařízeními (E2E šifrování)
  • Offline režim s merge konflikty
  • Sdílené pracovní prostory
  • Historie změn / undo tree
  • Import z Markdown / Tana export

Fáze 4 — Rozšíření

  • Graf vztahů mezi uzly
  • Kalendářní pohled (#Task s termínem)
  • AI asistent (automatické tagování, shrnutí)
  • Plugin API pro vlastní supertagy
  • Mobilní app (React Native)

Co potřebuji od vás ke schválení

1. Název aplikace — navrhuji Supertag Studio (můžete změnit)
2. Rozsah MVP — stačí Fáze 1, nebo rovnou Fáze 1+2?
3. Sync — stačí local-only na start, nebo je sync nutný hned?
4. Jazyk UI — čeština, angličtina, nebo obojí?
5. Přednastavené supertagy — #Task, #Person, #Project, #DailyNote, #Note — stačí?
6. Vizuální styl — tmavý (jako mockupy), světlý, nebo přepínatelný?

Technická architektura — Web + Windows ze stejné codebase

Frontend

  • React + TypeScript
  • Outliner: vlastní komponenta (nebo TipTap/ProseMirror)
  • Stav: Zustand nebo Jotai
  • Styling: Tailwind CSS
  • PWA pro web (offline, instalace)

Windows desktop

  • Tauri 2 (Rust shell, ~5 MB installer)
  • Stejný React bundle jako web
  • Nativní SQLite přes Tauri plugin
  • System tray, globální hotkey (volitelně)
  • Auto-update

Datový model

  • Node — id, parentId, content, order, createdAt
  • SupertagDef — name, color, fields[]
  • NodeTag — nodeId + supertagId + fieldValues
  • Query — saved filter expression
  • Workspace — container pro uzly a tagy

Sync (Fáze 3)

  • CRDT (Yjs) nebo vlastní op-log
  • Backend: Supabase / self-hosted
  • E2E šifrování (libsodium)
  • Konfliktní UI pro ruční merge
